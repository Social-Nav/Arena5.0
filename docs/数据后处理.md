## Pipeline 概览

```
采集（Isaac）        world 参数同时决定存储目录
   ↓                 <world>/data/episode_XXXXXX.json + videos/episode_XXXXXX_N.npy
阶段 1  几何标注      process_raw_to_dataset.py
   ↓                 npy → JPG/PNG + preview mp4，json → parquet，算 pixel goals，写 meta/
阶段 2  语义标注      annotate_with_instructions.py
   ↓                 读 preview mp4 → VLM → tasks.jsonl + episodes.jsonl
可训练数据集
```

```bash
# 1. 采集。world 既选场景，也决定存储目录
arena launch sim:=isaac robot:=Ai2_Bot2 world:=grscenes_1 \
    tm_robots:=scenario tm_obstacles:=scenario save_data:=true \
    social_yielding:=true

# 2. 几何标注（所有 world 一次过）
python process_raw_to_dataset.py --data-path src/social_gen/traj_data/grscenes

# 3. 语义标注
export API_KEY=sk-...
python annotate_with_instructions.py --data-path src/social_gen/traj_data/grscenes --use-vlm
```

两个阶段都可以指着 grscenes 根目录跑，自动遍历所有 world，只处理没处理过的，结尾打印汇总。
单条失败不中断整批，失败列表在结尾重复一遍，traceback 走 stderr。

## 相机安装参数

`postprocess/process_raw_to_dataset.py` 顶部，改机器人相机时改这里：

```python
ROBOT_MODEL      = "Ai2_Bot2"   # 从哪个 model_params.yaml 读 scale
CAMERA_FORWARD_M = 0.3506       # +x，机器人原点前方（未缩放）
CAMERA_LATERAL_M = 0.0          # +y，左侧（未缩放）
CAMERA_HEIGHT_M  = 1.6453       # +z，机器人原点上方（未缩放）
CAMERA_PITCH_DEG = 30           # 俯仰角，向下为正
```

三个偏移都是**未缩放的原始 USD 值**，缩放系数从
`arena_robots/robots/<ROBOT_MODEL>/model_params.yaml` 的 `scale` 读取（本机 0.8）。改机器人缩放
只改 yaml，这边自动跟随；**不要在这里复制一份 scale**。找不到 yaml 会回退 1.0 并打 WARN。

`CAMERA_HEIGHT_CM`（= 132）和目录名 `132cm_30deg` 都是派生的，不手工维护，所以不可能和实际
计算用的几何对不上。`annotate_with_instructions.py` 从这里 import。

俯角决定近处盲区 —— 地面要离机器人这么远才进画面，比这更近的 goal 一律投不出来：

| 俯角 | 盲区（机器人原点） | 可见地面带 |
|---|---|---|
| 15° | 1.31 m | 68% 画面高 |
| **30°（当前）** | **0.84 m** | **88% 画面高** |



采集分辨率在 `data_logger_replicator.py` 顶部（`CAPTURE_WIDTH/HEIGHT = 640/480`），一个常量被
render product 和内参换算共用，改的话改那一处。

## 阶段 1：几何标注

`process_raw_to_dataset.py`，一遍完成 npy 解包、动作离散化、pixel goal 计算和 meta 写入。

```bash
# 整个 grscenes 根目录，所有 world
python process_raw_to_dataset.py --data-path src/social_gen/traj_data/grscenes

# 单个 world
python process_raw_to_dataset.py --data-path src/social_gen/traj_data/grscenes/grscenes_1
```



处理顺序：

1. 读 `videos/episode_XXXXXX_N.npy`（按 N 数字排序）和 `data/episode_XXXXXX.json`
2. 从相机位姿推机器人位姿 → 离散化动作（前进/左转/右转/停）
3. 写 RGB JPG、depth PNG、preview mp4，并**校验数量**，对不上就报错退出
4. 用内存里的 depth 算 pixel goals（不重读 PNG）
5. 写 parquet 和 `meta/`
6. 清理原始输入：raw npy **和** `data/episode_XXXXXX.json`

### Pixel Goal

Farthest Visible Goal（Wei et al. 2025）：沿未来轨迹找最远的、当前帧可见的**机器人脚印**
（地面位置，不是相机中心），投影成像素坐标。搜索范围是弧长 `--lookahead`（5 m），太近的
（`--min-ground-dist`）跳过，被遮挡的（depth 比几何距离近超过 `--margin`）跳过。

投脚印而非相机中心是因为脚印才是机器人真能驶到的位置；投相机中心在近处会偏几十像素。

无效 goal 写哨兵值 `[-1, -1]` 和 `-1`,**不是 null** —— 筛选用 `goal[:,0] >= 0`。

### 原始数据的清理

转换成功后 npy 和 json 都会删掉，这也是重跑时跳过该 episode 的依据。**原始数据只有这一份，
删了要重跑 Isaac**，所以删除前有两处检查：parquet 必须能读回、且行数与刚写入的一致。

要保留就添加参数 `--keep-src`。注意这样自动跳过会失效。

行人轨迹（json 里独有）已经搬进 parquet 的 `pose_peds` 列。

**相机内参没有留存。** 它在阶段 1 被读出并用于 pixel goal 投影（所以标签是准的），但 parquet 只
存算好的像素坐标，json 删掉后 fx/fy/cx/cy 就没了。目前可从 640×480 + hFOV 90° 精确反推，但目录名
`132cm_30deg` 不含这两个数 —— 混用不同相机配置的批次时需要额外记录。细节和处理方案见
`实现细节.md`。

## 阶段 2：语义标注

`annotate_with_instructions.py`。读阶段 1 产出的 preview mp4，调 Gemini（`gemini-2.5-pro`）
生成 R2R 风格的导航指令，写进 `meta/`。

```bash
export API_KEY=sk-...        # 只从环境变量读，源码里绝不硬编码
python annotate_with_instructions.py --data-path src/social_gen/traj_data/grscenes --use-vlm

# 用预生成的 instructions，不调 VLM
python annotate_with_instructions.py --data-path src/social_gen/traj_data/grscenes \
    --instructions instructions.json

# 不加 --use-vlm 也不加 --instructions → 用 placeholder，先把管线跑通
python annotate_with_instructions.py --data-path src/social_gen/traj_data/grscenes
```


默认复用 `meta/episodes.jsonl` 里已有的真实 instruction，要全部重新生成加 `--redo`。

只跑阶段 2 不会动 PNG 和 parquet 的标签，只改 instruction 相关字段，所以换一批 instruction
不需要重跑转换。

## 目录结构

一个 world 一个数据集，没有 scenario 层也没有时间戳层。重跑同一个 world 会接着已有 episode
往后编号，不覆盖。

```
src/social_gen/traj_data/grscenes/<world>/
  data/
    episode_000000.json                      采集产物，转换后删除
    chunk-000/episode_000000.parquet         阶段 1 产物：带 pixel goals
  videos/
    episode_000000_0.npy                     采集产物，转换后删除
    chunk-000/
      observation.images.rgb.132cm_30deg/
        episode_000000_0.jpg                 有损，quality 95
      observation.images.depth.132cm_30deg/
        episode_000000_0.png                 uint16 毫米（1000 = 1m），必须无损
      preview/
        episode_000000_rgb.mp4               8-bit h264，阶段 2 的输入
  meta/
    info.json                                阶段 1 写，阶段 2 更新 total_tasks
    episodes_stats.jsonl                     阶段 1 写：逐 feature 统计
    tasks.jsonl                              阶段 2 写：去重后的 instruction
    episodes.jsonl                           阶段 2 写：episode → instruction
  snapshots/
    2026-08-24_14-30-05/                     让行快照，不是数据集的一部分
```

原始文件和转换产物共用 `data/` 和 `videos/`，靠 `chunk-XXX` 这一层区分。

`snapshots/` 由 `save_snapshots:=true|false`（**默认 false**）控制。这个参数只控制 replan 读完之后是否保留。

### parquet 列

```
action                                int32     -1 无动作 / 0 停 / 1 前进 / 2 左转 / 3 右转
pose.132cm_30deg                      4x4 f32   相机位姿（世界系），不是机器人位姿
goal.132cm_30deg                      [u,v] i32 pixel goal，无效为 [-1, -1]
relative_goal_frame_id.132cm_30deg    int32     goal 在几帧之后，无效为 -1
pose_peds                             struct    {p_1: [16 f32], ...}，每人一个展平的 4x4
timestamp                             float32
frame_index                           int64     每个 episode 从 0 重新开始
index                                 int64     跨整个数据集连续
episode_index / task_index            int64
```


## 参数详解

### process_raw_to_dataset.py

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--data-path` | 必需 | grscenes 根目录或单个 world 目录 |
| `--hfov` | 90.0 | 水平 FOV（度）。**仅在数据缺 `observation.camera_intrin` 时**用来推 intrinsics |
| `--depth-scale` | 1000.0 | PNG 单位/米，**必须 1000** |
| `--flip-v` | False | 翻转 v 坐标 |
| `--fps` | 30.0 | 采集帧率，写入 timestamp 和 meta/，并决定两个阈值的换算 |
| `--fwd-speed-thresh` | 0.05 | 前进判定的**速度**阈值（m/s） |
| `--yaw-speed-thresh-deg` | 8.0 | 转弯判定的**角速度**阈值（度/秒） |
| `--lookahead` | 5.0 | Goal 搜索的**弧长**预算（米），不是帧数 |
| `--margin` | 0.2 | 遮挡检测松弛量（米） |
| `--min-ground-dist` | 1.0 | 排除比这更近的脚印（米） |
| `--ground-z` | 0.0 | 地面平面的世界 z |
| `--depth-is-euclidean` | False | depth 存的是径向距离而非平面深度时才加 |
| `--instructions` | | 注入外部 instruction 的 JSON |
| `--keep-src` | False | 转换后保留 raw npy 和 json |


几处需要注意的参数：

- **`--depth-scale` 必须 1000**。采集侧已经乘过一次到毫米，改了会让遮挡检测整体失效
- **`--depth-is-euclidean` 保持 False**。采集侧用的是 `distance_to_image_plane`（平面深度 z），
  针孔反投影要的也是 z。搞成径向距离在画面边缘会差 1.4–1.5 倍，吃掉 `--margin` 的全部容错
- **`--hfov` 只是回退**。内参优先从每帧记录的 `observation.camera_intrin` 读（主点做过
  aperture-offset 修正）；用 hfov 重算会假设主点居中，静默破坏每一次反投影。回退时打 WARN
- **`--flip-v` 尚未实证验证**。采集侧已转成 ROS optical（+Y down），按理不需要再翻；若 goal
  点整体上下颠倒需要修改该参数

### annotate_with_instructions.py

| 参数 | 说明 |
|---|---|
| `--data-path` | 必需，grscenes 根目录或单个 world 目录 |
| `--use-vlm` | 调 VLM 生成，需要 `API_KEY` 环境变量 |
| `--instructions` | 用预生成的 JSON，跳过 VLM |
| `--redo` | 重新生成已有的 instruction（默认复用） |

`--instructions` 的 JSON 键是 episode index 的字符串形式，可以给单个文件也可以给目录（按
`<world>.json` 自动匹配）：

```json
{ "0": "Walk forward past the sofa...", "1": "Turn right at the doorway..." }
```
