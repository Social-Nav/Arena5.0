## 2. `arena_robots`

`model_params.yaml`（Ai2_Bot2）：

- `collision_monitor_sources` 去掉 `depth_pcl`：胸前摄像头深度点云延迟约 1.75 秒，远超
  `collision_monitor` 的 0.5 秒 `source_timeout`，每帧都被判定过期而忽略，只产生日志噪音；
  移除后无功能损失（该 polygon 本就禁用，节点只是透传）。
- `depth_pcl` 保留为 costmap 数据源（local + global）：激光雷达只是 z=0.1265 的单层平面，
  看不到悬空/低矮障碍物，深度点云仍是唯一能看到这些的传感器。延迟对静态场景无影响
  （TF 按时间戳做几何重投影），对移动行人有约 1.8 米滞后。
- `velocity_smoother_max_velocity` 的 vx 上限 0.6→0.8，与 social_mpc 的
  `optimizer.max_linear_velocity`（同为 0.8）对齐，核算过刹车距离与局部 costmap 可视范围。
- 同步更新 `deps/robot_usds` 指针。

## 3. `arena_isaac`

- `person.py`：修复行人出生朝向 bug——`Gf.Rotation` 需要角度制，之前直接传弧度值，朝向被
  压缩了 180/π 倍（如 88.8° 出生朝向实际显示成 1.55°）。
- `EditPrims.py`：修复差速轮控制器（`DifferentialController`）轮速缩放不匹配问题。
- `NavigatePedestrians.py`：修复行人卡死问题（idle 判定阈值 + 2D/3D 距离计算 bug）。
- `snapshot_capturer.py`：修复渲染产物命名冲突——Isaac 会回收未命名的
  "Replicator_NN" 渲染产物插槽，新截图请求可能借用到常驻管线（如后置摄像头深度点云）的
  产物，造成"首次截图正常、后续头部截图返回空白"。改为单调递增、永不回收的显式命名。
- `proactive_yielding_trigger.py` / `social_yielding_orchestrator.py`：主动让行功能主体
  代码，含 ROBOT 命名空间从 launch 参数读取的修复。
- `.gitignore`：新增一条本地专用忽略规则（保留被移除的 blockage-rule 触发逻辑参考副本）。

## 4. `Arena` 主仓库

### A. Scenario yaw 角度制修复

- `geometry.py` 新增共享转换器 `Pose.converter_deg`；`entities.py` 令
  `DynamicObstacle.pose` 使用它——行人出生朝向之前被当弧度解析，实际是角度制，误差可达
  上百度。
- `Scenario.py` 机器人朝向转换复用同一转换器（原来各写一份）。
- `hunav/__init__.py`：行人 yaw 不再硬编码为 0.0，改读真实朝向；waypoint 第三个元素
  （角度制航向）不再泄漏进 z 坐标（之前会让路径点飘到几十米高空）。

### B. 新增机器人社交行为 profile 推送功能（social_yielding）

  `robot:` 块读取。
- `robot_manager.py`（+259 行）：新增 `_push_params` 等方法，在 reset 时通过 ROS2
  `SetParameters` 服务把选定 profile 参数实时下发给 `controller_server` 与
  `global_costmap`，无需重启。
- `tasks/robots/scenario.py`：解析 `social_yielding` 优先级
  （launch 参数 > scenario 字段 > 默认 false），发布到新 latched topic
  `/social_yielding/enabled`。
- 新增 `configs/nav2/profiles/{passive,neutral,aggressive}/profile.yaml` 三套参数。

### C. Reset / 生命周期相关修复
