## 1. `robot_usds`

**头部相机俯角 15° → 30°**（`Ai2_Bot2.usda` 的 `head_link2/head_camera/d435/head_camera`）：

- 新四元数精确对应 30°（与 `T_ROBOT2CAMERA @ pitch_matrix(30)` 差 6.7e-16，核对时需先套采集侧的
  USD→ROS optical 转换）。
- `focalLength` 10 → 10.4775，配 `verticalAperture 15.71625`，hFOV 恰好 **90.00°**（旧值 92.67°，
  与后处理 `--hfov 90` 默认值不符）。
- 父级 `head_camera` Xform 钉成单位变换，安装偏移移到 Camera prim 自己身上（`translate (0.2, 0, 0)`）。
- 盲区从机器人原点 1.31 m 缩到 **0.84 m**，可见地面带从 68% 增到 88% 画面高。

`env/warehouse.usda`、`env/warehouse_with_forklifts.usda` 只是编辑器状态（viewport、预览相机绑定、
`back_camera` 设为不可见）。

> 偏移常量 `CAMERA_FORWARD_M` / `CAMERA_HEIGHT_M` **尚未针对新 USD 结构核对** —— base USD 是二进制
> crate，无 `pxr` 绑定解不出完整变换链。下次采集后比对 `pose.*` 的 z 平移是否仍是 1.3162 m 左右。

## 2. `nav2_social_costmap_plugin`

`social_layer.cpp`：`cutoff_ >= amplitude_` 分支提前 `return` 却没设 `current_ = true`，导致
`isCurrent()` 永远不为真，`controller_server` 陷入 "Costmap timed out" 死循环。

这个分支在**运行时**可达，不只是静态配置问题：`amplitude` 由社交 profile 的 `SetParameters` 实时
下发，而两个 profile 的 `cutoff` 都是 20.0，任何 `amplitude <= 20` 的新 profile 都会卡死控制器。

## 3. `obstacle_distance_manager`

未初始化变量导致发布栈垃圾：`final_idx` 声明后不赋值，空旷 costmap 下 `distanceTransform` 给出
celldist 65534 / label 0，三次环搜索全部落空，于是把栈上的随机值当索引发出去。

- `ObstacleDistance.msg` 新增 `int32 NO_OBSTACLE=-1`，消费方需先检查再当索引用。
- `final_idx` 初始化为该常量，类型从 `unsigned int` 改为 `int` 以容纳 -1。
- `look_label_in_distance` 留下哨兵值（`dist >= 9999999`）时 `continue`。

## 4. `nav2_social_mpc_controller`

**`/people` 坐标系写入副本（真 bug，影响行为）**：`for (auto p : people.people)` 是值拷贝，
`p.position = out_point.point` 写进副本就丢了，`people.people` 保留原坐标系的坐标。`/people` 在
`map` 系时，错误坐标系的行人会落进 `social_clear_distance` 内，`SocialWorkCost` 爆炸，机器人在远处
行人旁边就冻住。改成 `auto&`，并同步更新 `header.frame_id`。

**`computeObstacle` 返回 `std::optional`**：配合上面的 `NO_OBSTACLE`，空旷 costmap 下返回
`nullopt`，而不是拿垃圾索引继续算力。

**参数化**：`proxemics_d0` / `proxemics_alpha`（原为硬编码 0.5 / 3.0）、`max_linear_velocity`、
`desired_linear_vel`、`solver_time_budget`、`max_angular_velocity` 全部改成参数，并接进社交 profile
的动态参数回调，可运行时重调。注释区分了两个易混量：`max_linear_vel_` 是 Ceres 上界（bound），
`desired_linear_vel_` 是巡航目标（target）；另记下 `setSpeedLimit()` 按配置原值缩放而非当前值，
避免反复调用逐步趋零。

**诊断**：`[MOTION-DIAG]` 三处从 `WARN`/`INFO` 降为 `DEBUG`（`--log-level optimizer:=debug` 开回）；
新增命令链 taps（nav / smoothed / out 三级 vx 加各自 age）定位是哪一级吃掉了 vx —— age 是必要的，
值是粘滞的、永不回 NaN，单看 0.000 分不清"持续为零"和"启动时一次陈旧零值"；
`set_diagnostics_enabled()` 在让行暂停仿真时静音 `[STOP-DIAG]`；并修了诊断自身的 bug —— social /
proxemics 的 block id 没被记录，导致有人在视野内也打印 `social=0/prox=0`。

## 5. `arena_isaac`

### A. 后处理管线合并

`raw_data_convert.py` + `gen_pixel_goal_labels.py` → **`process_raw_to_dataset.py`**（前两者已删除），
`batch_instructions.py` → **`annotate_with_instructions.py`**。一遍完成，省掉一次 depth PNG 的
写-读循环，也保证 PNG 和标注用的是同一份 depth 数据。

修掉的标签几何问题：

- **内参从未被读取**：采集侧写进每帧的 `observation.camera_intrin`（主点做过 aperture-offset
  修正）一直被忽略，一律按 `--hfov 90` 重算并假设主点居中。
- **脚印投影**：`farthest_visible_goal` 投的是相机 xy 而非机器人脚印；且 `mount_matrix()` 当时
  不存在（两个纯旋转相乘求逆仍是纯旋转，平移列全零），所以"机器人轨迹"其实还是相机轨迹。
  两个错误叠加，必须先修 `mount_matrix()`。近处偏差 87 px。
- **STOP 标签恒等赋值**：`np.where(...)` 两分支都是 FORWARD，静止帧全被标成 FORWARD。
- **阈值帧率相关**：0.05 m/帧 在 30 fps 下是 1.5 m/s，改为 `--fwd-speed-thresh`（m/s）。转弯阈值
  同理改 `--yaw-speed-thresh-deg`（8 °/s）—— 旧的 5°/帧 = 150 °/s，超过机器人 86 °/s 上限，
  TURN 永不触发。
- **depth 双重缩放**：采集侧已乘到毫米，又乘一次，2000 mm × 1000 截断到 65535，深度图整张饱和。
- **`lookahead` 由 64 帧改为 5 m 弧长**：慢速场景下 64 帧只有 0.69 m，还没出盲区，goal 全为空。
- **`pose_peds` 静默丢列**：值读进了 `out_data`，但 `peds_type` 留成 `None`（一个 TODO），schema
  不声明该字段，`from_pydict` 建表时直接丢掉。行人轨迹只存在于 raw json，而 json 转换后会删除。
- **`index` 列整个缺失**、内容列改 int32，对齐 LeRobot v2.1 参考格式。
- **`task_index` 未回写 parquet**：阶段 1 一律写 0，`write_meta` 里算好的 `episode_to_task` 从未被
  使用，导致按 parquet 取 instruction 的 loader 把 episode 0 的指令配给所有 episode。

`episodes_stats.jsonl` 与 `info.json` 的 `features` 块改为完整 LeRobot v2.1 形状，统计从 parquet
现算，所以原始 npy 已删也能重建 `meta/`。

**转换成功后删除原始输入**（npy + `data/episode_XXXXXX.json`），这也是重跑时跳过的依据。删除前两道
闸：parquet 必须能读回、且行数与刚写入一致。`--keep-src` 可保留。

### B. 采集侧

## 2. `arena_robots`

`model_params.yaml`（Ai2_Bot2）：

- `collision_monitor_sources` 去掉 `depth_pcl`：胸前摄像头深度点云延迟约 1.75 秒，远超
  `collision_monitor` 的 0.5 秒 `source_timeout`，每帧都被判定过期而忽略，只产生日志噪音；
  移除后无功能损失（该 polygon 本就禁用，节点只是透传）。
- `depth_pcl` 保留为 costmap 数据源（local + global）：激光雷达只是 z=0.1265 的单层平面，
  看不到悬空/低矮障碍物，深度点云仍是唯一能看到这些的传感器。延迟对静态场景无影响
  （TF 按时间戳做几何重投影），对移动行人有约 1.8 米滞后。
- `velocity_smoother_max_velocity` 的 vx 上限 0.6→0.8，与 social_mpc 的
  `optimizer.max_linear_velocity`（同为 0.8）对齐，核算过刹车距离与局部 costmap 可视范围。
- 同步更新 `deps/robot_usds` 指针。
