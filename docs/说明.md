# `HOST_SCENES_DIR` 配置说明

因为要将USD资产挂载到容器，需要修改工作区根目录 `.env` 里的 `HOST_SCENES_DIR`。

示例：

```env
HOST_SCENES_DIR=/InternUtopia/internutopia/assets/scenes/GRScenes-100

```

把它改成自己机器上的数据目录即可。

仅修改挂载路径时应重新创建容器使 Compose 配置生效，不需要重新构建镜像。

# 替换场景 USD

在使用 `grscenes` 场景时，先打开当前场景配置里的 `world.yaml`，找到 `path` 字段指向的 `start_result_navigation.usd` 文件路径，例如：

```yaml
path: /path/to/grscenes/start_result_navigation.usd
```

然后用文件夹中的 `start_result_navigation.usd` 去替换这个路径下原有的同名文件。

# 数据采集启动命令

> `world` 可选：`grscenes_1` … `grscenes_30`，以及 `airport` / `hospital_1` / `hospital_2` /
> `office_1` / `reception`。每个 grscenes world 的标准 VLN 采集集为 `default`、
> `default_1`、`default_2`、`default_3`、`default_4`；部分 world 还包含单独的社交交互或
> 测试 scenario。完整列表见 `arena_simulation_setup/worlds/`。

```bash
arena launch \
  sim:=isaac \
  robot:=Ai2_Bot2 \
  world:=grscenes_1 \
  tm_robots:=scenario \
  tm_obstacles:=scenario \
  save_data:=true
```

**常用启动参数：**

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `sim` | — | 仿真后端，数据采集用 `isaac` |
| `robot` | `jackal` | 机器人型号，数据采集用 `Ai2_Bot2` |
| `world` | `map_empty` | 加载的场景（见上方可选列表） |
| `tm_robots` | `explore` | 机器人任务模式；场景采集用 `scenario`（按序读取 scenario.yaml 的机器人 waypoints） |
| `tm_obstacles` | `random` | 障碍/行人生成模式；场景采集用 `scenario` |
| `save_data` | `false` | `true` 时开启数据记录 |
| `save_snapshots` | `false` | 让行快照读完后是否保留（不是"抓不抓"，详见数据处理.md） |
| `headless` | `0` | 取值 `-1`/`0`/`1`/`2`：`-1` 显示全部环境，`0` 全显示，`1` 仅 RViz，`2` 什么都不显示 |
| `social_yielding` | `auto` | 主动让行开关，三态 `auto`/`true`/`false`；`true` 时调用 LLM 选让行点（需配置 `API_KEY`） |
| `local_planner` | `social_mpc` | 局部规划器，见下方「Nav2 local planner 选择」 |



- `save_data:=true` 时开启数据记录。存储位置由 `world` 决定，一个 world 一个数据集：

    ```
    src/social_gen/traj_data/grscenes/<world>/
    ├── meta/episodes.jsonl
    ├── data/chunk-000/episode_000000.parquet
    └── videos/chunk-000/
        ├── observation.images.rgb.132cm_30deg/episode_000000_{i}.jpg
        └── observation.images.depth.132cm_30deg/episode_000000_{i}.png
    ```

  没有 scenario 层也没有时间戳层。重跑同一个 world 时，logger 会同时检查尚未转换的 JSON 和
  已转换的 `data/chunk-*/episode_XXXXXX.parquet`，从当前最大 episode 编号继续，不覆盖已有数据。
  不传 `world` 时退回 `src/Arena/collected_data/<启动时间>/` 的旧布局。

  - **导航失败（aborted / canceled）** 时会删除该次已经写出的 NPY/JSON，不增加 episode 编号；
    下一次采集复用该编号。world-based 布局不会留下空 episode 文件夹。
  - 目录不存在时启动时会自动创建。

机器人多 waypoint 路线只有最终点成功才保存；中间 waypoint 与临时让行点 Y 的成功不会结束采集。
启用 social yielding 时，scene-ready 后仍有独立 motion hold：先等待全局路径、snapshot 和 LLM
选点，再等待匹配 Y 的新路径及 0.35 s 命令链稳定后放行。详细状态机见场景配置文档。

- `save_data:=false`（默认）时不记录数据，正常运行。

## 后处理

原始数据 → 可训练的 LeRobot 格式，两个脚本两个阶段。参数语义、pixel goal 算法、`meta/`
格式一律见 [数据处理.md](数据处理.md)，这里只给最短路径：

本地批量采集时不必手工执行下面两段 Python 命令；`collect_worlds_local.sh` 已在每个 world 的
stage-1 后自动完成 instruction 分配。下面命令用于单 world 调试、补 instruction 或 VLM。

```bash
source src/Arena/_meta/tools/source

# 阶段 1：几何标注（npy → PNG，json → parquet，算 pixel goals，写 meta/）
python3 -m arena_isaac.data_logging.postprocess.process_raw_to_dataset \
  --data-path src/social_gen/traj_data/grscenes

# human_interaction 固定 instruction：跳过视频生成和 VLM
python3 -m arena_isaac.data_logging.postprocess.process_raw_to_dataset \
  --data-path src/human_interaction/traj_data/grscenes \
  --skip-video
python3 -m arena_isaac.data_logging.postprocess.annotate_with_instructions \
  --data-path src/human_interaction/traj_data/grscenes \
  --instruction-type perpendicular_traffic

# 仍需要 VLM 语义标注时：阶段 1 不要加 --skip-video
export API_KEY=sk-...
python3 -m arena_isaac.data_logging.postprocess.annotate_with_instructions \
  --data-path src/social_gen/traj_data/grscenes --use-vlm
```

两个阶段都可以指着 grscenes 根目录跑，自动遍历所有 world，只处理没处理过的，结尾打印汇总。
单条失败不中断整批，失败的 episode 保留 raw npy，修好后重跑会自动只捡它。

只有需要 preview MP4 时才要求 PATH 中有 `ffmpeg`（含 libx264）。固定 instruction 或
`--instructions` 数据可给阶段 1 加 `--skip-video`，不生成 MP4 也不依赖 ffmpeg。
宿主机和容器需分别检查依赖；缺失时在实际执行后处理的容器内安装，详见
[数据处理.md](数据处理.md)。

> **阶段 1 默认会删掉原始数据。** 转换成功后该 episode 的 npy 和 `data/episode_XXXXXX.json`
> 会被删除（删除前校验 parquet 能读回且行数一致），这也是重跑时跳过它的依据。原始数据只有这
> 一份，删了要重跑 Isaac 才能拿回 —— 想留就加 `--keep-src`。

### 本地批量采集

宿主机上不需要先进入 Arena 容器，也可以直接批量采集。脚本会复用现有 Arena/Isaac Compose
项目，并在宿主机实时 tail 每个 world 的 `launch.log`：

```bash
bash src/Arena/scripts/colleague_collect/collect_worlds_local.sh \
  --manifest selection.txt \
  --dataset-root /opt/arena_ws/src/human_interaction/traj_data/grscenes \
  --instruction-type perpendicular_traffic
```

`--manifest` 可重复传入，脚本会把多个两列 manifest 合并；同一个 world 下重复的 scenario
会自动去重。例如：

```bash
bash src/Arena/scripts/colleague_collect/collect_worlds_local.sh \
  --manifest selection_perpendicular.txt \
  --manifest selection_following.txt \
  --manifest selection_overtaking.txt \
  --dataset-root /opt/arena_ws/src/human_interaction/traj_data/grscenes
```

如果同一批里混有多种 scenario 命名，例如 `robot_overtaking_008`、
`following_human_001`、`perpendicular_traffic_002`，可用 `auto` 让脚本根据
采集时显式记录的 `scenario -> episode_index` 映射自动生成逐 episode instruction：

```bash
bash src/Arena/scripts/colleague_collect/collect_worlds_local.sh \
  --manifest selection_overtaking.txt \
  --manifest selection_following.txt \
  --manifest selection_perpendicular.txt \
  --dataset-root /opt/arena_ws/src/human_interaction/traj_data/grscenes \
  --instruction-type auto
```

采集与后处理相关 CLI 参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--keep-raw` / `--no-keep-raw` | 删除 raw | `--keep-raw` 保留 raw JSON/NPY |
| `--skip-preview-video` / `--no-skip-preview-video` | 跳过 MP4 | `--no-skip-preview-video` 生成 preview MP4 并依赖 ffmpeg |
| `--instruction-type TYPE` | 空 | 非空时在几何转换后自动分配 instruction；`auto` 按显式 episode map 逐 episode 推断 |
| `--dataset-root PATH` | `src/social_gen/traj_data/grscenes` | 指定数据集根目录 |

宿主机/GPU 等运行环境仍使用环境变量控制，例如 `GPU_ID`、`REUSE_EXISTING_PROJECT`。

日志和 resume state 默认在：

```text
log/local_collect/<run>/
log/local_collect/state/<compose-project>/<selection-dataset-tag>/
```

manifest 的 state tag 会同时包含 world 和 scenario 列表；改变 scenario 集合会生成新的 state
目录，避免误用旧 completion 状态。`completed_worlds.txt` 跳过整个 world，
`scenario_state/<world>.txt` 跳过已成功 scenario，因此重跑同一命令是断点续采，只补失败项。
每个 state 目录下还会写入 `<world>.episode_map.tsv`，记录成功 scenario 对应的实际 episode 编号；
instruction auto 模式优先使用该文件，避免跨批次追加数据时错位。

## 配置 API_KEY（instruction 生成 / 让行选点）

VLN 指令生成（`annotate_with_instructions` / `instruction_generator`）和社交让行选点
（`social_yielding_selector`）都调用VLM，需要配置 API key。

两个调用点都从环境变量读取 `URL` 和 `API_KEY`，**不在源码里硬编码密钥**。
`.env` 保留 DMXAPI 与 RoboScience 两套 URL/key 配置，一次只激活一组；切换后重启 Arena launch。
让行选点调用 `URL` 对应网关的 `/v1/responses`，视频语义标注调用该网关的
`/v1beta/models/<model>:generateContent`。切换前确认目标网关支持对应接口。

```python
API_KEY = os.environ.get("API_KEY", "")
```

配置方式：在工作区根目录 `/opt/arena_ws/.env` 中写入（`source src/Arena/_meta/tools/source` 时会自动加载到环境）：

```env
URL=https://www.dmxapi.cn/v1
API_KEY=sk-xxxxxxxxxxxxxxxx
```

> - `.env` 位于工作区根目录 `/opt/arena_ws/`，不在代码仓库（`src/Arena`）跟踪范围内；不要把 key 写进任何提交的文件。
> - 未设置时脚本会打印 `API_KEY not set` 并跳过模型调用。
> - 当前语义标注用 `gemini-3.1-pro-preview`（Gemini native generateContent）；让行选点用
>   `gpt-5.6-terra`（`/v1/responses`）。模型名与接口以对应脚本常量为准。

## Nav2 local planner 选择

默认使用 **social_mpc**，可通过启动参数切换：

```bash
# Social MPC（默认）
arena launch ... local_planner:=social_mpc

# DWB
arena launch ... local_planner:=dwb

# Regulated Pure Pursuit
arena launch ... local_planner:=regulated_pure_pursuit
```

各 planner 配置文件位于 `src/Arena/arena_simulation_setup/configs/nav2/controllers/<planner_name>/controller_config.yaml`。

> 注意 `max_vel_x` / `max_speed_xy`（在 `arena_robots/.../model_params.yaml`）**只有 dwb 与
> regulated_pure_pursuit 读取**。social_mpc 的速度由
> `configs/nav2/profiles/<name>/profile.yaml` 的 `desired_linear_vel` 决定，详见
> [场景与社交配置说明.md](场景与社交配置说明.md)。

## 本地文件与 Upstream

`arena_simulation_setup/worlds/` 是本地场景数据目录，已加入主仓库 `.gitignore`。
主仓库与 `arena_isaac` 子仓库都忽略 `test/`、`tests/`、`test_*.py`、`*_test.py`，本地测试仍可运行，
新测试不进入普通 `git add`。文件命名规则只覆盖约定的测试名称，不会自动识别任意命名的诊断脚本。

`.gitignore` 不影响历史已跟踪文件。本机已对既有 worlds 设置 `skip-worktree`，保留远端已有
版本且隐藏本地变化；既有测试也按相同方式保护。该索引标记不随 push 传播，其他工作副本需自行
设置；合并/切换分支可能要求临时解除，不能视为永久防上传机制。不要 `git add -f` 强制添加这些文件。
本次没有删除远端文件，也没有重写 Git 历史。
