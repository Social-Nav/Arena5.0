# 文档结构

本文件是**总入口**，覆盖从环境配置到跑通一次采集的完整路径，每个环节只给最短可用步骤。
需要细节时进对应的**分支文档**，它们是本文件的详细补充，不重复入口内容：

| 文档 | 定位 | 什么时候进去 |
|---|---|---|
| **说明.md**（本文件） | 总入口 / 操作路径 | 配环境、启动采集、选 planner、查该看哪份文档 |
| [数据后处理.md](数据后处理.md) | 分支：后处理阶段详解 | 改后处理参数、看 pixel goal 算法、查 parquet 列与 `meta/` 格式、排后处理的错 |
| [场景与社交配置说明.md](场景与社交配置说明.md) | 分支：场景与社交参数详解 | 写 `scenario.yaml`、调社交 profile、查某个参数的取值约束 |
| [常见问题.md](常见问题.md) | 故障排查 | 报错了 |

写文档时的分工：**操作步骤和命令留在本文件，参数语义和实现细节放分支文档。** 同一件事不要
两边都写全 —— 本文件给命令加一条链接，细节只在分支文档里维护。

# `HOST_SCENES_DIR` 配置说明

因为要将USD资产挂载到容器，需要修改工作区根目录 `.env` 里的 `HOST_SCENES_DIR`。

示例：

```env
HOST_SCENES_DIR=/InternUtopia/internutopia/assets/scenes/GRScenes-100

```

把它改成自己机器上的数据目录即可。

使用前需先重建 `arena_isaac` 镜像：`arena feature isaac update`

# 替换场景 USD

在使用 `grscenes` 场景时，先打开当前场景配置里的 `world.yaml`，找到 `path` 字段指向的 `start_result_navigation.usd` 文件路径，例如：

```yaml
path: /path/to/grscenes/start_result_navigation.usd
```

然后用文件夹中的 `start_result_navigation.usd` 去替换这个路径下原有的同名文件。

# 数据采集启动命令

> `world` 可选：`grscenes_1` … `grscenes_30`，以及 `airport` / `hospital_1` / `hospital_2` /
> `office_1` / `reception`。36 个场景均已配好 scenario（每个 6–12 个），完整列表见
> `arena_simulation_setup/worlds/`。

```bash
arena launch \
  sim:=isaac \
  robot:=Ai2_Bot2 \
  world:=grscenes_1 \
  tm_robots:=scenario \
  tm_obstacles:=scenario \
  save_data:=true \
  social_yielding:=true
```

**常用启动参数：**

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `sim` | — | 仿真后端，数据采集用 `isaac` |
| `robot` | `jackal` | 机器人型号，数据采集用 `Ai2_Bot2` |
| `world` | `map_empty` | 加载的场景（见上方可选列表） |
| `tm_robots` | `explore` | 机器人任务模式；场景采集用 `scenario`（读 scenario.yaml 里的起终点） |
| `tm_obstacles` | `random` | 障碍/行人生成模式；场景采集用 `scenario` |
| `save_data` | `false` | `true` 时开启数据记录 |
| `save_snapshots` | `false` | 让行快照读完后是否保留（不是"抓不抓"，详见数据后处理.md） |
| `headless` | `0` | 取值 `-1`/`0`/`1`/`2`：`-1` 显示全部环境，`0` 全显示，`1` 仅 RViz，`2` 什么都不显示 |
| `social_yielding` | `auto` | 主动让行开关，三态 `auto`/`true`/`false`；`true` 时调用 LLM 选让行点（需配置 `API_KEY`） |
| `local_planner` | `social_mpc` | 局部规划器，见下方「Nav2 local planner 选择」 |



- `save_data:=true` 时开启数据记录。存储位置由 `world` 决定，一个 world 一个数据集：

    ```
    src/social_gen/traj_data/grscenes/<world>/
    ├── data/episode_XXXXXX.json            ← 每帧参数（相机内外参、行人状态）
    ├── videos/episode_XXXXXX_N.npy         ← 每帧一个，内含 rgb + depth
    └── snapshots/<时间戳>/                  ← 让行快照（save_snapshots:=true 时保留）
    ```

  没有 scenario 层也没有时间戳层，重跑同一个 world 会接着已有 episode 往后编号，不覆盖。
  不传 `world` 时退回 `src/Arena/collected_data/<启动时间>/` 的旧布局。

  - **导航失败（aborted / canceled）** 的 episode 会保留空文件夹作为标记，不写入任何数据。
  - 目录不存在时启动时会自动创建。

- `save_data:=false`（默认）时不记录数据，正常运行。

## 后处理

原始数据 → 可训练的 LeRobot 格式，两个脚本两个阶段。参数语义、pixel goal 算法、`meta/`
格式一律见 [数据后处理.md](数据后处理.md)，这里只给最短路径：

```bash
source src/Arena/_meta/tools/source

# 阶段 1：几何标注（npy → PNG + mp4，json → parquet，算 pixel goals，写 meta/）
python3 -m arena_isaac.data_logging.postprocess.process_raw_to_dataset \
  --data-path src/social_gen/traj_data/grscenes

# 阶段 2：语义标注（读 preview mp4 → VLM → instruction）
export API_KEY=sk-...
python3 -m arena_isaac.data_logging.postprocess.annotate_with_instructions \
  --data-path src/social_gen/traj_data/grscenes --use-vlm
```

两个阶段都可以指着 grscenes 根目录跑，自动遍历所有 world，只处理没处理过的，结尾打印汇总。
单条失败不中断整批，失败的 episode 保留 raw npy，修好后重跑会自动只捡它。

> **阶段 1 默认会删掉原始数据。** 转换成功后该 episode 的 npy 和 `data/episode_XXXXXX.json`
> 会被删除（删除前校验 parquet 能读回且行数一致），这也是重跑时跳过它的依据。原始数据只有这
> 一份，删了要重跑 Isaac 才能拿回 —— 想留就加 `--keep-src`。

> `raw_data_convert` 和 `gen_pixel_goal_labels` 已被 `process_raw_to_dataset` 取代并删除；
> `batch_instructions` 已被 `annotate_with_instructions` 取代并删除。

## 配置 API_KEY（instruction 生成 / 让行选点所需）

VLN 指令生成（`annotate_with_instructions` / `instruction_generator`）和社交让行选点
（`social_yielding_selector`）都通过 DMXAPI 网关调用视觉模型，需要一个 API key。

脚本统一从环境变量 `API_KEY` 读取，**不在源码里硬编码**：

```python
API_KEY = os.environ.get("API_KEY", "")
```

配置方式：在工作区根目录 `/opt/arena_ws/.env` 中写入（`source src/Arena/_meta/tools/source` 时会自动加载到环境）：

```env
API_KEY=sk-xxxxxxxxxxxxxxxx
```

> - `.env` 位于工作区根目录 `/opt/arena_ws/`，不在代码仓库（`src/Arena`）跟踪范围内；不要把 key 写进任何提交的文件。
> - 未设置时脚本会打印 `API_KEY not set` 并跳过模型调用。
> - 涉及的模型：指令生成用 `gemini-2.5-pro`，让行选点用 `gpt-5.4`（均经 DMXAPI 网关）。

## Nav2 local planner 选择

默认使用 **social_mpc**，可通过启动参数切换：

```bash
# Social MPC（默认）
arena launch ... local_planner:=social_mpc

# DWB
arena launch ... local_planner:=dwb

# Regulated Pure Pursuit
arena launch ... local_planner:=regulated_pure_pursuit
```

各 planner 配置文件位于 `src/Arena/arena_simulation_setup/configs/nav2/controllers/<planner_name>/controller_config.yaml`。

> 注意 `max_vel_x` / `max_speed_xy`（在 `arena_robots/.../model_params.yaml`）**只有 dwb 与
> regulated_pure_pursuit 读取**。social_mpc 的速度由
> `configs/nav2/profiles/<name>/profile.yaml` 的 `desired_linear_vel` 决定，详见
> [场景与社交配置说明.md](场景与社交配置说明.md)。
