## Pipeline 概览

```
采集（Isaac）        world 参数同时决定存储目录
   ↓                 <world>/data/episode_XXXXXX.json + videos/episode_XXXXXX_N.npy
阶段 1  几何标注      process_raw_to_dataset.py
   ↓                 npy → JPG/PNG（可选 preview mp4），json → parquet，算 pixel goals，写 meta/
阶段 2  语义标注      annotate_with_instructions.py
   ↓                 固定 instruction 读 parquet；VLM 模式读 preview mp4
可训练数据集
```

```bash
# 1. 采集。world 既选场景，也决定存储目录
arena launch sim:=isaac robot:=Ai2_Bot2 world:=grscenes_1 \
    tm_robots:=scenario tm_obstacles:=scenario save_data:=true \
    social_yielding:=true

# 2. 几何标注（所有 world 一次过）
python process_raw_to_dataset.py --data-path src/social_gen/traj_data/grscenes

# 3a. 固定 human-interaction instruction，不生成/读取视频
python annotate_with_instructions.py --data-path src/social_gen/traj_data/grscenes \
    --instruction-type perpendicular_traffic

# 3b. 仍需 VLM 时，不要给阶段 1 加 --skip-video
export API_KEY=sk-...
python annotate_with_instructions.py --data-path src/social_gen/traj_data/grscenes --use-vlm
```

两个阶段都可以指着 grscenes 根目录跑，自动遍历所有 world，只处理没处理过的，结尾打印汇总。
单条失败不中断整批，失败列表在结尾重复一遍，traceback 走 stderr。

批量采集时更推荐直接用 `collect_worlds_local.sh`，它在每个 world 内自动完成上述
“几何标注 + instruction 分配”：

```bash
bash src/Arena/scripts/colleague_collect/collect_worlds_local.sh \
  --manifest selection.txt \
  --dataset-root /opt/arena_ws/src/human_interaction/traj_data/grscenes \
  --instruction-type perpendicular_traffic
```

混合多种 interaction type 时把 `--instruction-type` 改为 `auto`。下面手动命令主要用在
单 world 调试、补 instruction、替换 instruction，或者 VLM 模式。

## 处理顺序约束

human-interaction 数据如果混有多种 interaction type，且 instruction 要在采集后自动对应写入，
必须固定成这个顺序：

```text
collect + postprocess + --instruction-type auto
    ↓
filter
```

`--instruction-type auto` 不是靠 scenario 文件顺序猜，而是优先读 state 目录里的
`<world>.episode_map.tsv`。这个文件由 collector 记录“成功 scenario -> 实际 episode 编号”，
所以能覆盖跨批次追加、部分 episode 失败被跳过、断点续跑这些情况。

不要先 filter、后做混合 instruction：

- filter 会把 `episode_index` 和全局 `index` 重编号，但不会同步重映射旧的 `.episode_map.tsv`
- 之后再跑 `--instruction-type auto` 会读到旧 map，新 episode 对不上类型
- 固定 `--instruction-type TYPE` 又只能给整批数据同一个 instruction，无法区分混合类型

如果全部 episode 本来就是同一种 instruction，先 filter 后固定标注也能工作；但统一按上面的
顺序处理最安全。

追加一批新数据时，回到**原始、未过滤的 source dataset** 继续跑：

```text
collect + postprocess + --instruction-type auto
    ↓
用更新后的 kept_episodes.txt 对 source dataset 重新 filter
```

不要在已经 filter 出来的目录上继续追加和重映射。collector 会跳过已完成的 scenario，并把新的
episode 编号追加进同一个 `.episode_map.tsv`；最后重新 filter 才能让 `episode.parquet` 文件名、
`episode_index`、全局 `index`、`task_index` 和 instruction 全部重新对齐。

## 相机安装参数

`postprocess/process_raw_to_dataset.py` 顶部，改机器人相机时改这里：

```python
ROBOT_MODEL      = "Ai2_Bot2"   # 从哪个 model_params.yaml 读 scale
CAMERA_FORWARD_M = 0.3506       # +x，机器人原点前方（未缩放）
CAMERA_LATERAL_M = 0.0          # +y，左侧（未缩放）
CAMERA_HEIGHT_M  = 1.6453       # +z，机器人原点上方（未缩放）
CAMERA_PITCH_DEG = 30           # 俯仰角，向下为正
```

三个偏移都是**未缩放的原始 USD 值**，缩放系数从
`arena_robots/robots/<ROBOT_MODEL>/model_params.yaml` 的 `scale` 读取（本机 0.8）。改机器人缩放
只改 yaml，这边自动跟随；**不要在这里复制一份 scale**。找不到 yaml 会回退 1.0 并打 WARN。

`CAMERA_HEIGHT_CM`（= 132）和目录名 `132cm_30deg` 都是派生的，不手工维护，所以不可能和实际
计算用的几何对不上。`annotate_with_instructions.py` 从这里 import。

俯角决定近处盲区 —— 地面要离机器人这么远才进画面，比这更近的 goal 一律投不出来：

| 俯角 | 盲区（机器人原点） | 可见地面带 |
|---|---|---|
| 15° | 1.31 m | 68% 画面高 |
| **30°（当前）** | **0.84 m** | **88% 画面高** |

> 俯角 2026-09-01 从 15° 改为 30°（USD commit `27997ec`）。同一次改动把安装偏移移到了 Camera
> prim 自己身上，所以那两个偏移常量**尚未针对新结构核对**。下次采集后比对 `pose.*` 的 z 平移
> 是否仍是 1.3162 m 左右即可确认。

采集分辨率在 `data_logger_replicator.py` 顶部（`CAPTURE_WIDTH/HEIGHT = 640/480`），一个常量被
render product 和内参换算共用，改的话改那一处。

Social yielding snapshot 的 head/back 画幅也为 `640x480`（4:3），由
`social_yielding/snapshot_capturer.py` 的 `_HEAD_BACK_RES` 控制；topdown 仍为 `1024x1024`。
两处只对齐分辨率与宽高比，不意味着不同相机的位姿和内参相同。
采集结束现在以 robot 的 `route_status` 为准：中间 waypoint 或临时让行 Y 成功不会提前保存，
只有原始路线最终成功才保存；路线 abort/cancel 则丢弃本次未完成数据。

## 阶段 1：几何标注

`process_raw_to_dataset.py`，一遍完成 npy 解包、动作离散化、pixel goal 计算和 meta 写入。

```bash
# 整个 grscenes 根目录，所有 world
python process_raw_to_dataset.py --data-path src/social_gen/traj_data/grscenes

# 单个 world
python process_raw_to_dataset.py --data-path src/social_gen/traj_data/grscenes/grscenes_1
```

耗时 ~10 分钟 / 100 episodes。

### FFmpeg 依赖

预览 MP4 只在阶段 2 使用 VLM 时需要。固定 instruction（`--instruction-type`）或预生成
instruction（`--instructions`）不会读取视频，因此阶段 1 可以加 `--skip-video` 跳过预览 MP4
和 ffmpeg 依赖：

```bash
python process_raw_to_dataset.py \
    --data-path src/human_interaction/traj_data/grscenes \
    --skip-video
```

不跳过时，脚本直接通过 subprocess 调用 PATH 中的 `ffmpeg`，使用 `libx264`、`yuv420p` 编码；
奇数宽高仅补齐边缘，不缩放原始画面。
在执行后处理的同一个环境中确认：

```bash
command -v ffmpeg
ffmpeg -version
# Ubuntu / Arena 容器内缺失时安装
sudo apt-get update
sudo apt-get install -y ffmpeg
```

宿主机已安装不代表容器内可用。当前检查曾确认宿主机有 `/usr/bin/ffmpeg`，而 Arena 容器没有；
这不是数据损坏，也不是需要 colcon rebuild 的问题。不必为了当前容器补装依赖重构整个镜像，
但容器被删除重建后需重新安装，或将依赖纳入镜像。安装 `imageio-ffmpeg` 并不保证当前脚本能
找到系统 `ffmpeg` 命令。失败 episode 保留原始数据，修好依赖后重跑原命令即可。

`--data-path` 支持绝对路径、当前目录相对路径，以及工作区根目录相对路径。

处理顺序：

1. 读 `videos/episode_XXXXXX_N.npy`（按 N 数字排序）和 `data/episode_XXXXXX.json`
2. 从相机位姿推机器人位姿 → 离散化动作（前进/左转/右转/停）
3. 写 RGB JPG、depth PNG；未加 `--skip-video` 时再写 preview mp4，并**校验数量**，对不上就报错退出
4. 用内存里的 depth 算 pixel goals（不重读 PNG）
5. 写 parquet 和 `meta/`
6. 清理原始输入：raw npy **和** `data/episode_XXXXXX.json`

### Pixel Goal

Farthest Visible Goal（Wei et al. 2025）：沿未来轨迹找最远的、当前帧可见的**机器人脚印**
（地面位置，不是相机中心），投影成像素坐标。搜索范围受两个距离共同约束：累计弧长
`--lookahead`（5 m），以及目标与当前位置在世界坐标系 XY 平面的距离
`--max-goal-distance`（4 m）。未来轨迹第一次超过 4 m 半径时立即截断，不再检查后续帧。
太近的（`--min-ground-dist`）跳过，被遮挡的（depth 比几何距离近超过 `--margin`）跳过。

投脚印而非相机中心是因为脚印才是机器人真能驶到的位置；投相机中心在近处会偏几十像素。

无效 goal 写哨兵值 `[-1, -1]` 和 `-1`,**不是 null** —— 筛选用 `goal[:,0] >= 0`。

### 原始数据的清理

转换成功后 npy 和 json 都会删掉，这也是重跑时跳过该 episode 的依据。**原始数据只有这一份，
删了要重跑 Isaac**，所以删除前有两道闸：parquet 必须能读回、且行数与刚写入的一致。

要保留就加 `--keep-src`。当前脚本没有 `--overwrite-existing` 参数；保留 raw 后重跑前应备份已有
产物，并确认当前脚本对已有 parquet 的处理，不能把它当成只读操作。

json 里独有的两样东西已经搬进了转换产物：相机内参 → `info.json`,行人轨迹 → parquet 的
`pose_peds` 列。

## 阶段 2：语义标注

`annotate_with_instructions.py`。VLM 模式读阶段 1 产出的 preview mp4，调 Gemini
（`gemini-3.1-pro-preview`）生成 R2R 风格的导航指令，写进 `meta/`。

`collect_worlds_local.sh` 已经在本阶段前自动调用这个脚本：固定 type 会直接赋值，
`auto` 会先生成逐 episode map 再赋值。单独运行本节命令只应在需要重新补 instruction、
更换 instruction 类型或走 VLM 时使用。

`--instruction-type` 和 `--instructions` 不需要视频：它们从
`data/chunk-*/episode_XXXXXX.parquet` 发现 episode，只更新 `tasks.jsonl`、`episodes.jsonl`、
`info.json` 的 `total_tasks`，以及 parquet 的 `task_index`。

```bash
export API_KEY=sk-...        # 只从环境变量读，源码里绝不硬编码
python annotate_with_instructions.py --data-path src/social_gen/traj_data/grscenes --use-vlm

# 用预生成的 instructions，不调 VLM
python annotate_with_instructions.py --data-path src/social_gen/traj_data/grscenes \
    --instructions instructions.json

# 为 following_human 数据直接添加对应的固定 instruction，不调 VLM
python annotate_with_instructions.py --data-path src/social_gen/traj_data/grscenes/grscenes_1 \
    --instruction-type following_human

# 不指定任何 instruction 来源 → 用 placeholder，先把管线跑通
python annotate_with_instructions.py --data-path src/social_gen/traj_data/grscenes
```

耗时 ~30-60 分钟 / 100 episodes。串行处理，限流或卡住只影响当条。

当前接口采用 Gemini 原生 `generateContent`：
`URL` 指定网关根地址（可带 `/v1`，脚本会拼接 `/v1beta/models/gemini-3.1-pro-preview:generateContent`）。
密钥统一从 `API_KEY` 读取，通过
`x-goog-api-key` 请求头发送；视频以 base64 `inlineData` 和文本 prompt 一起放入 JSON 请求。
它与 social yielding 的 Responses API 是两条独立调用链；切换网关时应同时切换 `.env` 中
的 `URL` 和 `API_KEY`，并确认网关支持 Gemini 原生接口。

默认复用 `meta/episodes.jsonl` 里已有的真实 instruction，只为缺的付费（placeholder 和
`FAILED_GENERATION_EP*` 都算缺）。要全部重新生成加 `--redo`。

只跑阶段 2 不会动 PNG 和 parquet 的标签，只改 instruction 相关字段，所以换一批 instruction
不需要重跑转换。

## 目录结构

一个 world 一个数据集，没有 scenario 层也没有时间戳层。重跑同一个 world 时，logger 同时扫描
未转换的 `data/episode_XXXXXX.json` 和已转换的 `data/chunk-*/episode_XXXXXX.parquet`，从最大
编号继续。正常流程中成功转换会删除同编号 raw 输入，因而再次指向根目录时自动跳过已完成
episode。使用 `--keep-src` 后再次处理同编号数据前应先检查已有 parquet，当前 CLI 没有覆盖开关。

```
src/social_gen/traj_data/grscenes/<world>/
  data/
    episode_000000.json                      采集产物，转换后删除
    chunk-000/episode_000000.parquet         阶段 1 产物：带 pixel goals
  videos/
    episode_000000_0.npy                     采集产物，转换后删除
    chunk-000/
      observation.images.rgb.132cm_30deg/
        episode_000000_0.jpg                 有损，quality 95
      observation.images.depth.132cm_30deg/
        episode_000000_0.png                 uint16 毫米（1000 = 1m），必须无损
      preview/
        episode_000000_rgb.mp4               8-bit h264，阶段 2 的输入
  meta/
    info.json                                阶段 1 写，阶段 2 更新 total_tasks
    episodes_stats.jsonl                     阶段 1 写：逐 feature 统计
    tasks.jsonl                              阶段 2 写：去重后的 instruction
    episodes.jsonl                           阶段 2 写：episode → instruction
  snapshots/
    2026-08-24_14-30-05/                     让行快照，不是数据集的一部分
```

原始文件和转换产物共用 `data/` 和 `videos/`，靠 `chunk-XXX` 这一层区分。

`snapshots/` 由 `save_snapshots:=true|false`（**默认 false**）控制。它不是"抓不抓"——让行的
replan 要从磁盘读快照，不落盘等于让行不可能发生；这个参数只控制 replan 读完之后是否保留。
调让行管线时开它，快照是 LLM 当时"看到什么才选了这个让行点"的唯一记录。

### parquet 列

```
action                                int32     -1 无动作 / 0 停 / 1 前进 / 2 左转 / 3 右转
pose.132cm_30deg                      4x4 f32   相机位姿（世界系），不是机器人位姿
goal.132cm_30deg                      [u,v] i32 pixel goal，无效为 [-1, -1]
relative_goal_frame_id.132cm_30deg    int32     goal 在几帧之后，无效为 -1
pose_peds                             struct    {p_1: [16 f32], ...}，每人一个展平的 4x4
timestamp                             float32
frame_index                           int64     每个 episode 从 0 重新开始
index                                 int64     跨整个数据集连续
episode_index / task_index            int64
```

内容列是 int32,LeRobot 记账列是 int64,遵循 LeRobot v2.1 参考格式。

**`pose.*` 存的是相机位姿**（采集侧原样透传），因为那才是实际测量值。机器人位姿是
`extrinsics @ cam_to_robot_footprint()` 算出来的中间量，只用于动作离散化和脚印投影，不落盘。

### 只重算几何标签

后续 Isaac datalogger 默认直接以 3 FPS 采集。如果 parquet、depth PNG 和相机 pose 已经存在，
只需要重新计算几何标签，可以使用独立脚本：

```bash
python relabel_geometry.py \
    --data-path src/social_gen/traj_data/grscenes \
    --fps 3 \
    --fwd-speed-thresh 0.1 \
    --yaw-speed-thresh-deg 15
```

`relabel_geometry.py` 当前固定面向 Ai2_Bot2 head_camera，不读取 raw JSON、model YAML 或实时 TF。
内参固定为 `fx=fy=387.878783`、`cx=320`、`cy=240`；camera-to-robot-footprint 矩阵与
`process_raw_to_dataset.py` 的 `cam_to_robot_footprint(30)` 一致。因此如果换了机器人或相机，
需要同时改两个脚本中的 Ai2_Bot2 常量和矩阵。

它不会抽帧，也不会改变 parquet 行数；它只重写 `action`、`goal.<setting>`
和 `relative_goal_frame_id.<setting>`，并同步 `meta/episodes_stats.jsonl`、每个 world 的
`meta/info.json` 统计。`frame_index`、`timestamp`、`index`、episode length、`task_index`、
task 映射和 instruction 内容保持不变。它不会重新生成 JPG、depth PNG、preview MP4，也不会删除
raw 文件。

`--fps` 表示现有 parquet 的采样频率，当前固定为 `3`。脚本支持把 `--data-path` 指向
`grscenes` 根目录，会自动遍历下面所有已经转换的 world 目录。动作阈值 `0.1 m/s` 和
`15 deg/s` 会按照现有 3 FPS 换算为相邻 parquet 行之间的判定阈值。

当前几何重标注默认值为：前向速度 `0.1 m/s`，转向角速度 `15 deg/s`。完整转换脚本的 CLI
默认值也已同步；需要临时覆盖时直接传对应参数。

如果在服务器上单独复制脚本运行，`relabel_geometry.py` 和
`process_raw_to_dataset.py` 需要放在同一目录，因为前者复用后者的 `discretize_actions` 和
`farthest_visible_goal` 几何函数。

### 生成 selection manifest

使用 `scripts/colleague_collect/make_selection.sh` 生成两列 manifest：

```bash
bash src/Arena/scripts/colleague_collect/make_selection.sh \
  --worlds 22,24,27 \
  --scenario-range 1 40 \
  --interaction-type following_human \
  --out selection_following.txt
```

这会生成：

```text
grscenes_22 following_human_001
grscenes_22 following_human_002
...
```

`--interaction-type` 会把 scenario 目录前缀设置为对应名称。旧式名称仍可用：

```bash
--scenario-prefix custom_name
```

### 按 kept_episodes 过滤数据

`scripts/filter_kept_episodes.py` 根据 `kept_episodes.txt` 中列出的 parquet 绝对路径，
复制对应 episode 的 parquet、RGB/depth 帧、preview，并按 0..N-1 重新编号后重建
该 world 的 `meta/`：

```bash
python3 src/Arena/scripts/filter_kept_episodes.py \
  --kept src/human_interaction/kept_episodes.txt \
  --output-name human_interaction_filtered \
  --overwrite
```

常用参数：

```text
--kept          kept_episodes.txt 路径
--source-root   源 human_interaction 根目录；不传时从 kept 文件推断
--output-name   新顶层目录名，默认 human_interaction_filtered
--overwrite     覆盖已存在输出目录
--dry-run       只打印计划
```

输出目录位于 `src/<output-name>/`，只改变最上层名称，`traj_data/grscenes/...` 以下结构不变。
parquet 的 `episode_index` 会重新编号，`index` 会按整个过滤数据集连续重写；`task_index`
保持不变，`tasks.jsonl` 只保留被选中 episode 使用的 task，因此每个 episode 仍对应原 instruction。

## 参数详解

### process_raw_to_dataset.py

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--data-path` | 必需 | grscenes 根目录或单个 world 目录 |
| `--hfov` | 90.0 | 水平 FOV（度）。**仅在数据缺 `observation.camera_intrin` 时**用来推 intrinsics |
| `--depth-scale` | 1000.0 | PNG 单位/米，**必须 1000** |
| `--flip-v` | False | 翻转 v 坐标 |
| `--fps` | 3.0 | 采集帧率，写入 timestamp 和 meta/，并决定两个阈值的换算 |
| `--fwd-speed-thresh` | 0.1 | 前进判定的**速度**阈值（m/s） |
| `--yaw-speed-thresh-deg` | 15.0 | 转弯判定的**角速度**阈值（度/秒） |
| `--lookahead` | 5.0 | Goal 搜索的**弧长**预算（米），不是帧数 |
| `--max-goal-distance` | 4.0 | Goal 距当前位置的世界坐标 XY 距离上限（米）；首次超过后截断未来路径 |
| `--margin` | 0.2 | 遮挡检测松弛量（米） |
| `--min-ground-dist` | 1.0 | 排除比这更近的脚印（米） |
| `--ground-z` | 0.0 | 地面平面的世界 z |
| `--depth-is-euclidean` | False | depth 存的是径向距离而非平面深度时才加 |
| `--instructions` | | 注入外部 instruction 的 JSON |
| `--keep-src` | False | 转换后保留 raw npy 和 json |
| `--skip-video` | False | 跳过 preview MP4 生成和 ffmpeg 依赖；JPG/PNG、parquet、meta 仍会写 |

两个已弃用参数 `--fwd-thresh` / `--yaw-thresh-deg` 直接接受逐帧量，给了会覆盖上面对应那个并
打 NOTE。**阈值按速度而非逐帧位移给**，因为逐帧量离开帧率没有意义。当前默认 3 FPS 时，启动时
会打印换算结果，两种单位都给：

```
  action threshold: forward > 0.03333 m/frame (= 0.100 m/s at 3.0 fps), turn > 5.0000 deg/frame
```

几个不该乱改的：

- **`--depth-scale` 必须 1000**。采集侧已经乘过一次到毫米，改了会让遮挡检测整体失效
- **`--depth-is-euclidean` 保持 False**。采集侧用的是 `distance_to_image_plane`（平面深度 z），
  针孔反投影要的也是 z。搞成径向距离在画面边缘会差 1.4–1.5 倍，吃掉 `--margin` 的全部容错
- **`--hfov` 只是回退**。内参优先从每帧记录的 `observation.camera_intrin` 读（主点做过
  aperture-offset 修正）；用 hfov 重算会假设主点居中，静默破坏每一次反投影。回退时打 WARN
- **`--flip-v` 尚未实证验证**。采集侧已转成 ROS optical（+Y down），按理不需要再翻；若 goal
  点整体上下颠倒就是这里

### annotate_with_instructions.py

| 参数 | 说明 |
|---|---|
| `--data-path` | 必需，grscenes 根目录或单个 world 目录 |
| `--use-vlm` | 调 VLM 生成，需要 `API_KEY` 环境变量 |
| `--instructions` | 用预生成的 JSON，跳过 VLM |
| `--instruction-type TYPE` | 为所有 episode 添加指定 social interaction 类型的固定 instruction，跳过 VLM |
| `--instruction-config PATH` | 指定 instruction YAML；默认使用 postprocess 目录中的配置 |
| `--redo` | 重新生成已有的 instruction（默认复用） |

5 条固定 instruction 定义在 postprocess 目录的 `social_interaction_instructions.yaml` 中，以
`following_human`、`frontal_approach`、`perpendicular_traffic`、`robot_overtaking` 和
`entering_room` 为键。instruction 内容只描述机器人与行人的交互行为，不依赖视频中的家具、
房间或其他场景物品。比如
`--instruction-type following_human` 会把对应文本添加到本次 `--data-path` 下发现的每个
episode。该模式不会读取视频内容或调用 VLM，且不能与 `--instructions`、`--use-vlm` 同时使用。
脚本会检查 YAML 是否恰好包含这 5 个名称，以及每条 instruction 是否为非空字符串。

`--instructions` 的 JSON 键是 episode index 的字符串形式，可以给单个文件也可以给目录（按
`<world>.json` 自动匹配）：

```json
{ "0": "Walk forward past the sofa...", "1": "Turn right at the doorway..." }
```
